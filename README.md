# Linux — Personal Configurations

Personal, portable configuration for a Linux/WSL development environment. The
repository does two jobs:

1. **Distributable AI agent configuration** — a single [APM](https://github.com/danielmeppiel/apm)
   package (`personal-configurations`) that ships coding standards, agents,
   skills, hooks, and MCP servers to any repo and to any supported agent
   (Kiro, Claude, Codex). `.apm/` is the source of truth; the native
   `.kiro/`, `.claude/`, and `.codex/` directories are generated by
   `apm install` and are git-ignored.
2. **Environment setup guides and assets** — reproducible notes and files for
   setting up a Linux/WSL workstation: terminal (zsh) customization, language
   tooling help, and ready-to-run Docker Compose stacks for local databases.

## Purpose

Keep one versioned source of truth for how the development environment and AI
coding agents are configured, so the same standards and tooling can be applied
consistently across machines and repositories instead of being copied by hand.

## Repository structure

```text
.
├── apm.yml                  # APM package manifest (name, targets, MCP deps)
├── apm.lock.yaml            # Resolved dependency lockfile
├── .apm/                    # SOURCE OF TRUTH for the agent package
│   ├── agents/              # Custom agent definitions
│   ├── instructions/        # Coding standards / steering (security, gitflow, commits, ...)
│   ├── hooks/               # Agent hooks (e.g. engram-save-on-stop)
│   └── skills/              # Reusable agent skills (commit-workflow, create-pr, ...)
├── apm-templates/           # Selective per-repo APM consumer templates
│   ├── coding/              # Coding-standards variants (+engram, +global combos)
│   ├── global/              # Global-config variants (wsl / no-wsl, +engram)
│   ├── engram/              # Standalone engram memory template
│   ├── mcps/                # MCP-only template
│   └── aws/                 # AWS-focused template
├── docker_applications/     # Local service stacks
│   ├── MYSQL/               # docker-compose.yml
│   └── POSTGRESQL/          # docker-compose.yml (+ pgAdmin)
├── programming_languages/   # Quick-reference help notes (python, java, nodejs, docker)
├── terminal-customization/  # zsh / Oh My Zsh / Powerlevel10k setup guide + drive mount scripts
├── preferences/             # Editor/agent preference files (kiro)
└── .agents/apm/             # APM restructure research, manifest, and reports
```

Generated, machine-local, and secret paths are git-ignored: `.kiro/`,
`.agents/` output, `.claude/`, `.codex/`, `*mcp.json*`, `apm_modules/`,
`.engram/`, and any `.env` / key files.

### The APM package

`apm.yml` declares the package as `personal-configurations`, targeting
`kiro`, `claude`, and `codex`. Primitives under `.apm/{instructions,agents,skills,hooks}/`
are auto-discovered by layout (not listed in `apm.yml`). The only declared
dependency is the **engram** MCP server (persistent agent memory), run over
stdio via the `engram` binary on `PATH`.

`apm-templates/` holds smaller, selective consumer manifests so a target repo
can pull just what it needs (e.g. only coding standards, only the global
config, or only engram) instead of the whole package. Each template folder has
its own `apm.yml` and `README.md` with per-OS install steps.

## Prerequisites

Target environment: **Linux (Ubuntu) or WSL with zsh**. Commands below use
`apt`; adapt for other distros.

### Core tools

```bash
sudo apt update && sudo apt install -y git zsh curl
```

### APM CLI (required to install the agent package)

```bash
curl https://aka.ms/apm-unix | sh
# binary installs to ~/.local/bin/apm — ensure ~/.local/bin is on your PATH
apm --version
```

### engram (agent memory MCP — required by apm.yml)

`engram` is a standalone statically-linked binary expected on `PATH` (the
package calls it as the bare command `engram`). Install it and confirm:

```bash
engram --version   # e.g. 3.0.0
```

### Docker (optional — only for the database stacks)

Needed to run anything under `docker_applications/`:

```bash
# Follow https://docs.docker.com/engine/install/ubuntu/ for Docker Engine + Compose plugin
docker --version && docker compose version
```

## Installation

### 1. Clone

```bash
git clone <this-repo-url> ~/Linux
cd ~/Linux
```

### 2. Install the agent configuration

Install the package for your agent target. The native config directory
(e.g. `.kiro/`) is generated from `.apm/`:

```bash
apm install --target kiro     # or: --target claude | --target codex
```

For a global (cross-repo) install and for pulling selective templates, follow
the per-OS steps in the relevant `apm-templates/<variant>/README.md`.

> **Secrets:** the GitHub MCP server reads `GITHUB_PERSONAL_ACCESS_TOKEN` from
> the environment. Export it (never commit it) before starting the agent:
> `export GITHUB_PERSONAL_ACCESS_TOKEN=...`

### 3. (Optional) Terminal customization

See [`terminal-customization/README.md`](terminal-customization/README.md) for
the full zsh + Oh My Zsh + Powerlevel10k setup, aliases, and drive-mount scripts.

### 4. (Optional) Local databases

```bash
docker compose -f docker_applications/POSTGRESQL/docker-compose.yml up -d
docker compose -f docker_applications/MYSQL/docker-compose.yml up -d
```

The default compose credentials are for **local development only** — change
them before exposing any service.
